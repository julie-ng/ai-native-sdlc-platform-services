# Documentation site

An [Astro](https://astro.build/) site using the [Starlight](https://starlight.astro.build/) documentation theme. It combines two generated references so the architecture can be reviewed without reading code:

| Section | Source | Plugin | URL path |
| --- | --- | --- | --- |
| HTTP API | [`docs/api/artifact.openapi.json`](../docs/api/artifact.openapi.json), generated from Zod by `npm run generate:artifact-openapi` | [starlight-openapi](https://github.com/HiDeoo/starlight-openapi) ([docs](https://starlight-openapi.vercel.app/getting-started/)) | `/http-api/` |
| Code reference | JSDoc in `server/utils/` and `server/db/` | [starlight-typedoc](https://github.com/HiDeoo/starlight-typedoc) ([docs](https://starlight-typedoc.vercel.app/getting-started/)), which runs [TypeDoc](https://typedoc.org/) with [typedoc-plugin-markdown](https://typedoc-plugin-markdown.org/) | `/code/` |

Both plugins regenerate their pages on every build, so the site always reflects the committed code and contract. Once the Pages workflow is in place (see [Deployment](#deployment)), the site is published at <https://julie-ng.github.io/ai-native-sdlc-platform-services/>.

## Commands

This is a separate npm package with its own lockfile, so documentation dependencies stay out of the app. Install the root dependencies first: TypeDoc (and Vite) read the Nuxt-generated tsconfig that the root `npm ci` creates.

```bash
npm ci                      # repository root, runs nuxt prepare
npm ci --prefix docs-site   # this package
```

Run from the repository root:

| Command | Purpose |
| --- | --- |
| `npm run docs:dev` | Dev server at <http://localhost:4000/ai-native-sdlc-platform-services/>, reloading on content, style and source changes |
| `npm run docs:check` | Fail on undocumented exports or broken `{@link}`s in the JSDoc scope |
| `npm run docs:build` | `docs:check`, then the static site into `docs-site/dist/` |
| `npm run preview --prefix docs-site` | Serve the built `dist/` locally to check the production output |

> [!NOTE]
> The site is configured for the GitHub Pages subpath (`base` in `astro.config.mjs`), so locally it lives under `/ai-native-sdlc-platform-services/`, not `/`.

## How it fits together

```text
docs-site/
├── astro.config.mjs        # Site URL/base, Starlight options, plugins and sidebar
├── typedoc.json            # JSDoc scope and validation, shared by the site and docs:check
├── tsconfig.json           # Keeps the site's TypeScript separate from the Nuxt app
├── public/                 # Copied as-is (favicon.svg)
└── src/
    ├── content.config.ts   # Registers Starlight's docs collection
    ├── route-data.ts       # Route middleware that reshapes the generated sidebar
    ├── openapi-overrides.mjs  # Vite plugin that swaps selected starlight-openapi components
    ├── components/         # Sidebar override and starlight-openapi replacements (Tailwind)
    ├── styles/             # Tailwind setup, design tokens and starlight-openapi wrapper styles
    └── content/docs/       # Pages: every .md/.mdx file becomes a route
        ├── index.md        # Home page
        └── code/           # Generated by starlight-typedoc; git-ignored, do not edit
```

The HTTP API pages are generated in memory and are not written to `src/`.

- **Code reference scope:** edit `typedoc.json`, not `astro.config.mjs`. Output formatting (one page per module, tables, code-block signatures) is in the `typeDoc` options in `astro.config.mjs`. TypeDoc paths there are relative to this folder (`../server/...`). The plugin skips TypeDoc validation, so `build` runs `check` first.
- **HTTP API:** edit the Zod schemas or `scripts/openapi/artifact-http.ts`, then `npm run generate:artifact-openapi`. Never edit the JSON by hand.

## Adding handwritten pages

Create a Markdown or MDX file under `src/content/docs/`; its path is its URL (`src/content/docs/guides/setup.md` becomes `/guides/setup/`). Each page needs a `title` in its frontmatter.

The sidebar is configured explicitly, so new pages do not appear in it until added to `sidebar` in `astro.config.mjs`, for example `{ slug: 'guides/setup' }` or a whole folder with `{ label: 'Guides', items: [{ autogenerate: { directory: 'guides' } }] }`. `src/route-data.ts` only reshapes the HTTP API and Code reference groups. See [Sidebar navigation](https://starlight.astro.build/guides/sidebar/) and [Authoring content](https://starlight.astro.build/guides/authoring-content/), which covers asides (`:::note`), tabs, cards and code blocks.

## Styles and components

The design follows [Scalar](https://scalar.com/)'s API reference: neutral colors, a flat sidebar, and quiet constraint text. Tailwind is set up through [Starlight's Tailwind support](https://starlight.astro.build/guides/css-and-tailwind/#tailwind-css).

| What | Where | How |
| --- | --- | --- |
| Colors, fonts, heading sizes | `src/styles/global.css` | Tailwind `@theme` tokens. `@astrojs/starlight-tailwind` maps the `accent` and `gray` scales to Starlight's `--sl-*` variables, so generated pages pick them up. HTTP method colors are `--color-method-*` tokens with dark-mode values. |
| Sidebar | `src/components/Sidebar.astro`, `SidebarEntries.astro` | Overrides Starlight's `Sidebar` only ([overriding components](https://starlight.astro.build/guides/overriding-components/)); keeps its scroll persistence and mobile footer. |
| Sidebar structure | `src/route-data.ts` | [Route middleware](https://starlight.astro.build/guides/route-data/): groups modules by folder and lists each module's members, read from the generated `## Functions`-style headings. HTTP API operations are grouped by their OpenAPI tag (resource), set in `scripts/openapi/artifact-http.ts`. |
| HTTP API rows, types, constraints, method label | `src/components/openapi/` | Tailwind replacements for starlight-openapi's `Key`, `Tag`, `Tags`, `Type` and `OperationMethodBadge`, swapped in by `src/openapi-overrides.mjs`. All other plugin components are unchanged. |
| HTTP API panels, media type, object schemas | `src/styles/openapi.css` | `@apply` rules on the plugin's class names, for wrappers whose logic depends on plugin internals. |

Prefer Tailwind utilities in components and `@apply` with theme tokens in CSS; change tokens rather than individual colors.

> [!IMPORTANT]
> starlight-openapi has no override API. The swap and the wrapper styles depend on its internal file names, props and class names, which can change in any release. It is pinned to an exact version: after upgrading, compare the overridden files in `node_modules/starlight-openapi/components/` and check the HTTP API pages. If this becomes tedious, rendering the HTTP API pages ourselves from the OpenAPI JSON is the alternative.

Other options: logo, fonts and social links in `astro.config.mjs` ([customization](https://starlight.astro.build/guides/customization/)); a landing page with `template: splash` ([frontmatter](https://starlight.astro.build/reference/frontmatter/)).

## Deployment

[`.github/workflows/docs.yml`](../.github/workflows/docs.yml) builds this package on every push to `main` (or manually) and deploys `docs-site/dist/` to GitHub Pages. Pages must use "GitHub Actions" as its source, a one-time repository setting. Pull requests do not build the site. A failing `docs:check` stops the deployment, so the published site never shows undocumented exports.

## Troubleshooting

- **`Tsconfig not found …/.nuxt/tsconfig.app.json`**: run the root `npm ci` (or `npx nuxt prepare`) first.
- **`… does not have any documentation`**: an export in `server/utils/` or `server/db/` lacks JSDoc. Document it; see the JSDoc rule in [AGENTS.md](../AGENTS.md).
- **`The collection "i18n" does not exist` / `Entry docs → 404 was not found`**: harmless build warnings; the site has no translations or custom 404 page.
- **Old pages after a rename**: delete `src/content/docs/code/` and `.astro/`; both are regenerated.
- **`npm audit` findings**: three high findings come from `starlight-openapi` → `httpsnippet` → `form-data`. They run only at build time to generate code snippets from our own spec and do not ship in the static output.
